Send receipts into SplitEase.

Overview

This API accepts normalized receipt details from a receipt processor, script, or other service. Your processor can start with a PDF, image, email, or store export, but it must extract the items and calculate the totals before calling the API. Send JSON, not the original file.

1

Read any receipt

Use your own parser or workflow to identify merchant, date, items, charges, and refunds.

2

Submit strict JSON

Send one validated receipt to the endpoint with a stable retry key. No authorization header is needed.

3

Review in SplitEase

The receipt appears as pending. A person reviews it and selects Import split; submission does not import it automatically.

Supported receipt categories are grocery, grocery_delivery, restaurant, retail, and other. Use other for a source outside the named categories.

Open access

No account or secret token is required.

Anyone with this page can submit a valid receipt to the shared Pending receipts inbox. Send a POST request to the endpoint below; the only required headers are Content-Type and Idempotency-Key.

The SplitEase workspace is shared: people who open the site can see pending receipt names, items, and totals. Submit only receipts appropriate for that public inbox.

Quick start

Endpoint

POST https://pooobzllagsownfpmrpf.supabase.co/functions/v1/receipt-import

Each request needs these headers:

HeaderValuePurpose
Content-Typeapplication/jsonThe body is one JSON receipt.
Idempotency-KeyStable unique key, 8–128 charactersReuse for retries of the same receipt. Allowed: letters, digits, ., _, :, -.

Save the complete example below as receipt.json, and replace the sample receipt ID and retry key with values unique to your receipt. Then run:

cURL · macOS / Linux
curl --fail-with-body -X POST \
  'https://pooobzllagsownfpmrpf.supabase.co/functions/v1/receipt-import' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: order-2026-10-09-1842' \
  --data-binary @receipt.json
PowerShell · Windows
$body = Get-Content -Raw -LiteralPath .\receipt.json
Invoke-RestMethod -Method Post `
  -Uri 'https://pooobzllagsownfpmrpf.supabase.co/functions/v1/receipt-import' `
  -Headers @{ 'Idempotency-Key' = 'order-2026-10-09-1842' } `
  -ContentType 'application/json' -Body $body

Choose a key derived from your source order ID. All callers share one receipt-ID namespace, so choose a globally unique external_receipt_id and keep it stable for retries. Retrying the identical body with the same key returns the same import ID. If the payload needs correction after submission, ask the site owner to dismiss it and submit under a new receipt ID and key.

Strict JSON format

All fields below are required. Do not include extra fields, null, formatted dollar strings, or decimal money values. Amounts are nonnegative integer US cents; for example, $8.98 is 898.

FieldType and rule
schema_versionNumber 1.
external_receipt_idStable nonempty source ID, at most 128 characters; unique across public submissions.
receipt_typegrocery, grocery_delivery, restaurant, retail, or other.
merchantNonempty name, at most 120 characters.
purchased_onReal calendar date in YYYY-MM-DD format.
currencyUSD only in v1.
itemsArray of 1–300 items, each in the exact format below.
subtotal_centsSum of charged and refunded item line totals; excludes not-charged items.
discount_centsOrder discount or savings.
tax_centsTax charged.
tip_centsTip charged.
delivery_centsDelivery charge.
order_refund_centsOther refund not already represented by a refunded item.
total_centsFinal amount charged after refunds. Must match the equation below exactly.

Each item

FieldType and rule
external_item_idUnique nonempty ID within this receipt, at most 128 characters.
nameNonempty product or service name, at most 200 characters.
quantityPositive number up to 1,000,000 with at most three decimal places. Weighted items are supported.
line_total_centsFull line amount in nonnegative integer cents, for the entire quantity. Do not send a per-unit price.
statecharged, refunded, or not_charged.

Text values must be trimmed and nonempty. Every listed cents field is required, even when its value is 0.

Refunds and totals

How item states work
  • charged: included in subtotal and final charge.
  • refunded: a full line refund. Include its original line amount in subtotal, then subtract it once from total.
  • not_charged: unavailable, cancelled, or never billed. Exclude it from subtotal and final charge, even if its listed line amount is positive.

Use order_refund_cents only for a refund that is not already shown as a refunded item. For a partial item refund, keep the item charged and put the partial refund in order_refund_cents. Do not subtract a refund twice.

subtotal_cents = sum(line_total_cents where state is charged or refunded)

total_cents = subtotal_cents - discount_cents + tax_cents + tip_cents + delivery_cents - order_refund_cents - sum(line_total_cents where state is refunded)

The calculation must match exactly in cents. If a source receipt includes an unmodeled fee or cannot be reconciled, flag it for manual review in your processor instead of inventing an item or changing another field to force a match.

Complete example

This delivery has one charged item, one fully refunded item, and one item that was never charged. Its total is $8.98.

receipt.json · copy and adapt
{
  "schema_version": 1,
  "external_receipt_id": "order-2026-10-09-1842",
  "receipt_type": "grocery_delivery",
  "merchant": "Example Market",
  "purchased_on": "2026-10-09",
  "currency": "USD",
  "items": [
    {
      "external_item_id": "milk",
      "name": "Whole milk",
      "quantity": 1,
      "line_total_cents": 499,
      "state": "charged"
    },
    {
      "external_item_id": "bread",
      "name": "Sourdough bread",
      "quantity": 1,
      "line_total_cents": 650,
      "state": "refunded"
    },
    {
      "external_item_id": "eggs",
      "name": "Eggs, unavailable",
      "quantity": 1,
      "line_total_cents": 399,
      "state": "not_charged"
    }
  ],
  "subtotal_cents": 1149,
  "discount_cents": 100,
  "tax_cents": 0,
  "tip_cents": 200,
  "delivery_cents": 299,
  "order_refund_cents": 0,
  "total_cents": 898
}

Accounting: 1149 - 100 + 0 + 200 + 299 - 0 - 650 = 898.

Responses and errors

A new valid request returns HTTP 201:

Success response
{
  "import_id": "a914ea83-22fd-4e51-a09f-96c319248db7",
  "status": "pending",
  "duplicate": false
}

An identical retry returns HTTP 200, the same import_id, duplicate: true, and the current status (pending, imported, or rejected). A successful submission appears in the website's Pending receipts inbox; a person still has to import it.

Errors use {"error":{"code":"TOTAL_MISMATCH","message":"Total does not reconcile","path":"$.total_cents"}}. The path appears for field validation errors.

HTTPMeaning and action
400Malformed JSON, invalid UTF-8, or missing/invalid idempotency key. Fix request.
405Use POST.
409Receipt ID or retry key already used with different data. Do not treat this as success.
413JSON body exceeds 256 KiB.
415Set Content-Type: application/json.
422Schema, item, subtotal, or total validation failed. Inspect error code and path.
429Rate limit reached. Wait, then retry the same body and key.
503Import service unavailable. Retry the same body and key later.

Limits and safety

  • At most 256 KiB per JSON request and 300 items per receipt.
  • At most 60 requests per minute across all public submitters.
  • Unknown fields are rejected. Version 1 uses USD only.
  • Use a stable, globally unique source receipt ID (for example, a UUID or source-prefixed ID) and idempotency key. Retrying with both unchanged is safe.
  • No token is needed. Browser clients can call the endpoint from any origin.
  • Receipt items and totals in the shared pending inbox can be viewed by site visitors. Avoid sending personal addresses, card data, or sensitive free text in item names.
